### Bug A — multi-coil fit result is discarded, but its failure still aborts the run

`raw.py:313` runs the spectral fit `for ich in range(self.nch)` × 15 echoes — **120
`curve_fit` calls for an 8-channel subject** — then throws every result away at `raw.py:362`:

```python
# this won't work for multiple coils yet
if self.nch == 1:
    ...append fRBC/fTP/RBCTPratio/TEeff...
```

Confirmed: `017AK` is `nch=8`, makes 120 calls, ends with `len(fRBC)=0`. But if *any one*
of those 120 discarded fits fails to converge, the `RuntimeError` propagates and kills the
whole reconstruction before any gas-phase output is written. `023DB`/`004LR`/`029CK`/
`032WS`/`005DS`/`02BB` are all `nch=8` and got lucky. `017AK` (spectral SNR ≈ 10) failed at
`iTE=27` and `iTE=48`.

**Fix — one line, cannot change any existing output** (results were already discarded):

```python
if(numspec > 0 and self.nch == 1):     # raw.py:313
```

Kills the entire `017AK` failure class and saves 120 pointless fits per multi-coil subject.

### Bug B — degenerate two-Lorentzian fit escapes into non-physical parameters

`lorfit` (`raw.py:13`) is two Lorentzians, 8 free params, fit with **unbounded `method='lm'`**,
and **warm-started across echoes** (`x0 = p.copy()`, `raw.py:348`).

**Not an SNR problem.** `007IT` has the *best* spectral SNR of the four single-coil subjects
and is the one that fails:

| subject | SNR @ iTE=0 | outcome |
|---|---|---|
| `007IT` | **539.6** | fails |
| `002BB` | 172.3 | fine |
| `019WR` | 17.0 | fine |
| `017AK` | 10.0 | fails (Bug A) |

At `iTE=0` 007IT's two peaks are **2 bins apart with amplitude ratio 1.02** — two nearly
identical Lorentzians, a rank-deficient Jacobian. LM has no bounds, so a negative linewidth
is legal, and one component flees off-resonance to act as a broad baseline (`diag_fit.py`):

```
007IT   iTE  peak_sep      w0         w1
          0      2.00   1.000      1.000
          1     88.13   2.257   -151.044     <-- w1 negative, component escapes
         14    346.41   2.287     -0.003

002BB   iTE  peak_sep      w0         w1
          1      9.39   2.365      2.575     <-- real two-peak solution, stays put
         14      6.96   2.512      3.285
```

Once it escapes, the warm start locks it in for all 15 echoes. The resulting parameters are
physically impossible:

| | fRBC range | spread | RBC/TP ratio |
|---|---|---|---|
| `002BB` | −138 … −52 Hz | 86 Hz | 0.156 … 0.272 |
| `007IT` | −380 … **+11248 Hz** | **11.6 kHz** | **−19.5 … −0.133** (negative!) |

**The critical consequence:** 007IT *"converged"* locally under scipy 1.17.1 and returned
`len(fRBC)=15`. The container's older scipy hit `maxfev` on the same runaway. **The
container is the honest one.** Loosening `maxfev` would make 007IT "run" and silently emit
a wrong dissolved-phase image.

⇒ `len(fRBC) > 0` is **not** sufficient to trust dissolved output. The guard checks only
that the list is non-empty, never that the parameters are physical.
⇒ `check_frbc.py` / `probe_nch.py` are faithful oracles for `nch=8` (fit never runs) but
**not** for `nch=1` (fit runs and can diverge differently per scipy version). Do not trust
a `nch=1` "guard silent" verdict as proof a subject will reconstruct. This is exactly the
mistake made with 007IT this session.

**Proposed fix (fork branch, `raw.py`):**
1. Gate the fit block on `self.nch == 1` (Bug A).
2. Replace unbounded `lm` with `method='trf'` + `bounds` forcing `w0, w1 > 0`, so 007IT
   fails loudly and reproducibly instead of differently per scipy version.
3. Re-seed `x0` from peak-picking each `iTE` instead of chaining, so one bad echo does not
   poison the rest.
4. Sanity-check after the fit: reject `RBCTPratio < 0` or `|fRBC − fTP|` outside a physical
   window, and fall back to gas-only via the existing guard.

**Nothing has been changed.** Root repo is commit-forbidden; these are fork-branch edits.

  `dyn_recon → convert_siemens_to_mrd`, so **launch batch with conda base python**.

  2nd-largest `.dat` as the breath-hold reference). `dyn_recon._clean_datadir()` symlinks
  around them. Any new script reading raw folders must filter `._*` itself.
- On a publish-stage kill, the Tyger recon has usually already finished — salvage the buffer
  (`tyger buffer read <id> > runs/<dir>/output.mrd`, id in `tyger.log`) then re-publish.
- `batch_recon.done_already()` requires the `p` output only when a pneumotach file exists
